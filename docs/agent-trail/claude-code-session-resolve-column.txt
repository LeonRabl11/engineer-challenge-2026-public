● Proposal

  1. What causes the overflow

  .history-list li is display: flex (styles.css:620–627). Its message <span> is
  a flex item, and flex items default to min-width: auto — meaning they refuse
  to shrink below the intrinsic width of their longest unbreakable token.
  =HYPERLINK(...) has no spaces, so its intrinsic min-width is huge, the span
  won't shrink, and it spills out of the panel. There's also no word-breaking
  rule, so even with room the long token wouldn't wrap.

  Fix: give the message span min-width: 0 (so it can shrink as a flex child) +
  overflow-wrap: anywhere (so the long token breaks). This requires a class on
  the span since it currently has none.

  2. Truncation cut mid-word

  ItemDetail.tsx:189 does historyItem.message.slice(0, 48) — a fixed 48-char JS
  slice, which is why it stops at "and the b" with no ellipsis. Fix: render the
  full message and clamp with CSS instead: -webkit-line-clamp on the same span
  gives a proper … at the end of the last visible line. Combined with
  overflow-wrap: anywhere from (1), long words also wrap before being clamped.

  3. Text alignment regardless of badge width

  The badge is the first flex item at its natural width, so "open" (narrow) vs
  "resolved" (wider) pushes the text start to different x positions. Fix: give
  the history badge a fixed width so every message begins at the same column,
  and switch the row to align-items: flex-start so the badge sits at the first
  line once text wraps to multiple lines.
